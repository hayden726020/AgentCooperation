# 基于文件系统的上下文工程规范 (Filesystem Context)

对话窗口是昂贵且容量有限的易失内存，而**文件系统是廉价且大容量的持久化外存**。通过将中间数据、状态快照和测试日志卸载到文件系统中，可以大幅降低上下文膨胀。

## 一、文件化上下文目录分工

| 目录路径 | 生命周期 | Git 属性 | 核心用途与内容 |
| :--- | :--- | :--- | :--- |
| **`.planning/`** | 长期受控 | **纳管入库** | 项目目标、阶段路线图、动态工作状态、模块代码库审计，作为跨会话唯一真实记忆源 |
| **`docs/`** | 长期受控 | **纳管入库** | 对外文档、模块接口契约、已知问题清单、架构图 |
| **`.runtime/`** | 本地运行时 | **.gitignore 忽略** | 临时备份快照（`.runtime/backup/`）、真实环境补丁、本地运行时状态 |
| **`.worktrees/`** | 任务隔离 | **.gitignore 忽略** | Git 独立工作树，供研发 Agent 进行代码修改与测试，物理隔离 master 工作区 |
| **`data/`** | 本地数据 | **.gitignore 忽略** | SQLite 生产库与 Mock 库，包含持久化的任务记录与执行账本 |

---

## 二、文件系统使用规范

1. **临时测试与调试脚本 (Scratch Files)**：
   - 调试脚本统一存放于临时目录（如 `.runtime/scratch/`），禁止直接散落在项目根目录下。
2. **测试日志外部化**：
   - 跑全量回归或大型排查时，命令输出通过管道重定向至 `.runtime/logs/<task_id>_test.log`。
   - 上下文中仅需使用正则或 grep 提取 summary 与 failure details，不得将几千行 log 全部灌入对话。
3. **工作树物理隔离**：
   - 多任务或多 Agent 并发开发时，通过 `git worktree add` 创建独立工作树，开发完成验证后由调度器合并或提交，严禁多个 Agent 同时在主工作区原地修改同一文件。
