# 上下文衰减诊断与治理规范 (Context Degradation)

在大规模或长周期的 AI 编程会话中，随着输入 Token 累积、工具返回日志堆叠，模型注意力机制会出现“上下文衰减”，导致关键指令被淹没、产生幻觉或反复修改同一错误。

## 一、上下文衰减典型症状

| 症状表现 | 根因分析 | 诊断标识 |
| :--- | :--- | :--- |
| **遗忘硬约束** | 早期规则被淹没在中间层（Lost-in-the-Middle） | 违背了单任务 GLM/DeepSeek 二选一或预算硬限额 |
| **死循环自修** | 工具报错信息过长，模型只关注最新报错而破坏原有正确逻辑 | 连续修错 > 2 次且引发新的回归报错 |
| **任务边界漂移** | 上下文中的历史讨论诱导模型试图修复不相关的历史债务 | 在一个 Bug 修复任务中去重构其他无关模块 |
| **重复读取文件** | 缺乏结构化索引，AI 无法确认文件内容是否已改变 | 连续 3 次以上 `view_file` 读取相同文件且未做修改 |
| **响应延迟激增** | 会话输入 Token 超过 100k，大量冗余工具输出堆积 | 每次工具调用前模型思考和传输时间显著上升 |

---

## 二、诊断与排毒流程 (Detox Protocol)

当观察到上述症状时，必须停止盲目的“继续修改”，执行排毒程序：

1. **截断与持久化 (Flush to Disk)**：
   - 提取当前已验证的代码事实和有效结论。
   - 将当前状态写入 `.planning/STATE.md` 或临时记录，禁止重要信息仅停留在对话窗口。

2. **清点事实与回退 (Rollback if needed)**：
   - 运行 `git diff` 检查工作区修改范围。
   - 若出现越界修改或代码已被带偏，立即使用 `git restore` 或从最后一次 checkpoint 恢复。

3. **短会话重置决策 (Context Reset)**：
   - 如果当前上下文已超过 80,000 Token 或累计报错日志过多，建议保存状态后结束当前会话，开启新会话。
   - 新会话仅加载 `.planning/STATE.md` 和目标任务约束，实现纯净上下文启动。
