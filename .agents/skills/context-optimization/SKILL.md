# 上下文优化与 Token 预算控制规范 (Context Optimization)

上下文优化的目标是**以最小的 Token 消耗，提供最精准的代码和约束信息**，最大化模型的推理质量与响应速度。

## 一、代码加载三不原则 (Negative Rules)

1. **禁止无目的全库遍历**：严禁在接到新任务后无目的地使用 `os.walk`、`dir /s` 或多层递归扫描读取整个仓库的每个源码文件。
2. **禁止预加载历史归档报告**：严格遵守工作指南，不读取 `docs/archive/`、旧版长篇验收报告或完整第三方库。
3. **禁止将大文件完整灌入 Prompt**：单个文件超过 1000 行时，只加载目标函数或类所在的行范围。

---

## 二、三级递进加载机制 (Progressive Disclosure)

当需要理解或修改代码时，严格按三级加载：

* **Level 1 (地图级，~500 Token)**：
  读取 `.planning/codebase/architecture.md` 识别涉及的子模块与职责划分。
* **Level 2 (符号级，~1,500 Token)**：
  使用针对性的符号检索或目录文件清单，定位到具体的 1-3 个核心文件及关键函数声明。
* **Level 3 (实现级，~4,000 Token)**：
  仅读取涉及修改的具体函数实现切片（配合 `StartLine`/`EndLine`）以及直接对应的单元测试用例。

---

## 三、KV Cache 友好型提示词结构

为最大化底层 LLM 的 KV-Cache 复用率，提示词结构应保持稳定前缀：

1. **静态前缀 (最前)**：系统指令、角色定义、安全规则（保持极少变动）。
2. **稳定技术约束 (次前)**：项目接口规范、测试命令模板。
3. **动态任务上下文 (居中)**：当前任务目标、涉及的局部代码切片。
4. **即时调用与证据 (末尾)**：最新的测试报错或复核审查裁决。
