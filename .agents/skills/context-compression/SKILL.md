# 上下文压缩与状态沉淀规范 (Context Compression)

长会话治理的核心在于**保留决策密度，消除冗余噪音**。通过将松散的对话历史压缩为高密度的结构化技术摘要，实现上下文的无损传递。

## 一、信息保留与剔除矩阵

| 必须保留 (High Value) | 必须压缩/剔除 (Low Value) |
| :--- | :--- |
| **已达成的技术决策**（如采用哪种数据结构） | 重复的头脑风暴与被否决的备选方案 |
| **已验证的代码事实**（如哪个测试通过） | 冗长完整的原始依赖树、pip list 原始打印 |
| **已修改的文件路径与关键 diff 摘要** | 几百行重复的编译器/测试套件标准输出 (stdout) |
| **未解决的具体报错行号与错误信息** | 中间推理过程中的试错步骤与自言自语 |
| **下一步具体可执行的明确指令** | 礼貌性用语、寒暄和重复声明的指令 |

---

## 二、状态沉淀四步模板 (State Distillation Template)

在压缩对话或持久化至 `.planning/STATE.md` 时，使用以下标准结构：

```markdown
### 任务状态沉淀快照 [<TIMESTAMP>]
* **任务标识**: <Task ID / Scope>
* **变更文件**:
  - `path/to/modified_file.py`: <一句话改动说明>
* **技术决策**: <关键选择及选择原因>
* **验证结果**:
  - 测试命令: `<cmd>`
  - 实际结果: `<X passed, Y failed in Z seconds>`
* **阻塞/遗留问题**: <无 / 具体遗留点>
* **下一步任务**: <下一个明确原子小任务>
```

## 三、观察屏蔽 (Observation Masking)

1. **终端输出控制**：
   - 运行大型测试时，使用 `-q`（quiet）或 `--tb=short`，禁止打印几百行全量 trace。
   - 原始长日志重定向保存到文件（如 `.system_generated/tasks/` 或 `.runtime/logs/`），上下文中仅读取包含 `FAILED` 或核心错误摘要的后 30 行。
2. **源码截取**：
   - 使用 `view_file` 时尽量指定精准的 `StartLine` 与 `EndLine`，严禁在无必要时一次性加载 800 行以上的完整文件。
